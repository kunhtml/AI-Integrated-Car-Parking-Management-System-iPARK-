II. ĐĂNG NHẬP VỚI EMAIL & MẬT KHẨU (backend/tests/auth.login.test.ts)
---------------------------------------------------------------------
1. TC-LOGIN-01: Đăng nhập bình thường thành công (khi chưa bật 2FA) → Trả về HTTP 200 OK + Cookie phiên làm việc + Dữ liệu người dùng.
   - Đầu vào (Body): { email: "test@example.com", password: "Password123!" }
   - Kết quả mong đợi:
     + Tìm kiếm tài khoản có email trùng khớp (không phân biệt chữ hoa, chữ thường).
     + So sánh mật khẩu khớp bằng `bcrypt.compare`.
     + Đóng gói session JWT Token bằng `signSession` và thiết lập cookie.
     + HTTP Status: 200.

2. TC-LOGIN-02: Đăng nhập thất bại do email không tồn tại trong hệ thống → Trả về HTTP 401 Unauthorized.
   - Đầu vào (Body): { email: "non-existent@example.com", password: "Password123!" }
   - Kết quả mong đợi:
     + HTTP Status: 401 với thông điệp "Email hoặc mật khẩu không chính xác."

3. TC-LOGIN-03: Đăng nhập thất bại do tài khoản đang bị khóa → Trả về HTTP 401 Unauthorized.
   - Đầu vào (Body): { email: "locked@example.com", password: "Password123!" }
   - Mock DB: Trạng thái tài khoản người dùng `status: "Bị khóa"`.
   - Kết quả mong đợi:
     + HTTP Status: 401 với thông điệp "Tài khoản của bạn đã bị khóa."

4. TC-LOGIN-04: Đăng nhập thất bại do nhập sai mật khẩu → Trả về HTTP 401 Unauthorized.
   - Đầu vào (Body): { email: "test@example.com", password: "WrongPassword" }
   - Mock DB: `bcrypt.compare` trả về `false`.
   - Kết quả mong đợi:
     + HTTP Status: 401 với thông điệp "Email hoặc mật khẩu không chính xác."

5. TC-LOGIN-05: Thiếu trường email khi đăng nhập → Ném lỗi xác thực dữ liệu (ZodError).
   - Đầu vào (Body): { password: "Password123!" }
   - Kết quả mong đợi:
     + Zod ném lỗi trước khi truy cập cơ sở dữ liệu.

6. TC-LOGIN-06: Thiếu trường password khi đăng nhập → Ném lỗi xác thực dữ liệu (ZodError).
   - Đầu vào (Body): { email: "test@example.com" }
   - Kết quả mong đợi:
     + Zod ném lỗi.

7. TC-LOGIN-07: Định dạng Email không hợp lệ khi đăng nhập → Ném lỗi xác thực dữ liệu (ZodError).
   - Đầu vào (Body): { email: "not-an-email", password: "Password123!" }
   - Kết quả mong đợi:
     + Zod ném lỗi định dạng email.

8. TC-LOGIN-08: Chuẩn hóa email nhập vào về dạng viết thường trước khi tìm kiếm.
   - Đầu vào (Body): { email: "TEST@EXAMPLE.COM", password: "Password123!" }
   - Kết quả mong đợi:
     + Gọi `User.findOne` truy vấn dạng chữ thường `{ email: "test@example.com" }`.

9. TC-LOGIN-09: Tài khoản có cấu hình 2FA (xác thực hai yếu tố) đang bật, nhưng đăng nhập chưa gửi kèm mã xác minh (twoFactorCode).
   - Đầu vào (Body): { email: "2fa-enabled@example.com", password: "Password123!" }

III. ĐĂNG NHẬP VÀ ĐĂNG KÝ VỚI TÀI KHOẢN GOOGLE (Google OAuth2)
----------------------------------------------------------------
1. TC-GLOGIN-01: Yêu cầu đăng nhập Google nhưng máy chủ chưa cấu hình Google Client ID/Secret → Trả về HTTP 503 Service Unavailable.
   - Kết quả mong đợi:
     + HTTP Status: 503 với thông điệp "Tính năng đăng nhập Google chưa được thiết lập."

2. TC-GLOGIN-02: Máy chủ đã cấu hình Google OAuth2 đầy đủ → Tạo mã bảo mật (state) và chuyển hướng trình duyệt đến trang đăng nhập Google.
   - Kết quả mong đợi:
     + Sinh mã state bằng ngẫu nhiên UUID dạng fixed, thiết lập cookie `google_oauth_state` kèm mã state này.
     + Chuyển hướng người dùng (Redirect) tới đường dẫn đăng nhập chính thức của Google (accounts.google.com).

3. TC-GLOGIN-03: URL chuyển hướng đăng nhập Google phải chứa đúng các cấu hình quyền (Scope) và tham số (Prompt).
   - Kết quả mong đợi:
     + URL chuyển hướng chứa: `scope=openid+profile+email` và `prompt=select_account`.

4. TC-GOOGLE-01: Người dùng mới liên kết qua Google → Đăng ký mới tài khoản với provider = "google" thành công.
   - Đầu vào (Query): { code: "auth_code", state: "valid-state" }
   - Kết quả mong đợi:
     + Lấy mã token Google và lấy thông tin tài khoản Google thành công.
     + Tạo tài khoản mới có cấu hình `{ provider: "google", googleId: "sub_123", email: "google@example.com", role: "customer" }`.
     + Đăng nhập, thiết lập session cookie và chuyển hướng về trang chủ Frontend (`http://localhost:3000`).

5. TC-GOOGLE-02: Tài khoản đã đăng ký bằng mật khẩu (credentials) nay chọn đăng nhập bằng Google trùng khớp Email → Tự động liên kết tài khoản (Update provider = "mixed").
   - Kết quả mong đợi:
     + Cập nhật thuộc tính `googleId` cho tài khoản hiện có.
     + Thay đổi `provider` của tài khoản sang `"mixed"`.
     + Không chạy hàm tạo tài khoản mới.
     + Chuyển hướng đăng nhập thành công.

6. TC-GOOGLE-03: Truy cập callback từ Google nhưng mã bảo mật (state) không khớp hoặc không hợp lệ → Trả về HTTP 400 Bad Request.
   - Kết quả mong đợi:
     + HTTP Status: 400 với thông điệp lỗi bảo mật (không gọi Google APIs để lấy thông tin).

7. TC-GOOGLE-04: Truy cập callback từ Google bị thiếu tham số xác thực `code` → Trả về HTTP 400 Bad Request.

8. TC-GOOGLE-05: Lỗi kết nối hoặc xử lý từ phía Google Token API → Trả về HTTP 502 Bad Gateway.

9. TC-GOOGLE-06: Lỗi kết nối hoặc xử lý từ phía Google Profile API → Trả về HTTP 502 Bad Gateway.

10. TC-GOOGLE-07: Tài khoản Google của người dùng chưa xác minh email (email_verified = false) → Trả về HTTP 502 Bad Gateway.

11. TC-GOOGLE-08: Tài khoản hiện tại có email trùng khớp với Google nhưng tài khoản này đang bị khóa trong hệ thống → Trả về HTTP 403 Forbidden.

12. TC-GOOGLE-09: Tài khoản tạo mới thông qua Google sẽ được thiết lập mật khẩu ngẫu nhiên đã mã hóa (không dùng mật khẩu trống hoặc đoán được).

13. TC-GOOGLE-10: Tài khoản đã có provider là "google", tiếp tục đăng nhập Google lần sau → Giữ nguyên giá trị provider là "google".
